# 移行計画レポート — COBOL（大規模）

## 1. 移行難易度評価

**工数見積もり: XL（超大規模）**

355ファイルの大規模COBOLシステムの移行は、日本のメガバンクや行政機関が何十億円もかけて取り組む難題です。技術的な移行より「業務知識の再現」が最大の難所です。

**最大ボトルネック:**
- 35年分の業務ロジックの解読と文書化
- テスト環境・テストデータの再現
- 本番切り替え時のダウンタイム最小化

---

## 2. 移行戦略の選択肢

| 戦略 | 概要 | メリット | デメリット | 推奨度 |
|---|---|---|---|---|
| 段階的リプレイス | 機能単位で少しずつ移行 | リスク分散、並行検証可能 | 長期化（5〜10年） | ⭐⭐⭐⭐⭐ |
| COBOL→Java自動変換 | Micro Focus等のツール活用 | 短期間 | コードが解読不能になる | ⭐⭐ |
| クラウドCOBOL | AWS Mainframe Modernization | インフラコスト削減 | COBOLのまま維持 | ⭐⭐⭐ |
| 全面刷新 | ゼロから現代システムで作り直し | 最もクリーン | 費用・期間・リスク最大 | ⭐⭐ |

**推奨: 段階的リプレイス**。全面刷新は失敗例が多い。

---

## 3. フェーズ別移行ロードマップ

- **Phase 1（即時〜6ヶ月）**: 全プログラムの業務ロジック文書化。依存マップ作成
- **Phase 2（6ヶ月〜2年）**: 影響範囲の小さい周辺機能からPython/Javaで再実装
- **Phase 3（2年〜5年）**: コアバッチ処理の段階的移行。新旧並行運用期間を設ける

---

## 4. 推奨移行先

| 現在 | 推奨 | 理由 |
|---|---|---|
| COBOL | Java / Python | エンタープライズ人材が豊富 |
| JCL | Apache Airflow | 視覚的なジョブ管理 |
| VSAM/ISAM | PostgreSQL | モダンなデータアクセス |
| メインフレーム | クラウド（AWS/Azure） | コスト最適化 |

---

## 5. 移行時の注意点

- **金額計算の精度**: decimal型で統一。floatは絶対禁止
- **文字コード**: EBCDIC→UTF-8変換での全角半角・特殊文字の確認
- **日付処理**: 和暦（昭和・平成・令和）対応が残っている可能性
- **並行運用**: 最低1年間は新旧システムで同じ計算を行い、結果を突合
