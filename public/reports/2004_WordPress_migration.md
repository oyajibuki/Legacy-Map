# 移行計画レポート — WordPress

## 1. 移行難易度評価

**工数見積もり: XL（超大規模・リスク最高）**

WordPressからの移行は世界中の企業が「やろうとして失敗する」最難関の一つです。技術的な移行より「プラグイン・テーマ・コンテンツの移行」と「SEO・URLの維持」が最大の難所です。

**最大ボトルネック:**
- 数千のプラグインとの互換性
- SEOの維持（URLパーマリンク構造）
- コンテンツのマークアップ（ショートコード依存）

---

## 2. 移行戦略の選択肢

| 戦略 | 概要 | メリット | デメリット | 推奨度 |
|---|---|---|---|---|
| WordPress維持 + セキュリティ強化 | 現状最適化 | リスク最小 | 技術的負債継続 | ⭐⭐⭐⭐⭐ |
| Headless WordPress | WP REST API + Next.js | フロントエンド近代化 | バックエンドWPのまま | ⭐⭐⭐⭐ |
| Contentful/Sanity移行 | ヘッドレスCMS | モダン設計 | コスト・移行コスト大 | ⭐⭐⭐ |
| Next.js + MDX | 完全移行 | 最高性能・安全 | コンテンツ移行が大変 | ⭐⭐⭐ |

---

## 3. フェーズ別移行ロードマップ

- **Phase 1（即時〜3ヶ月）**: Headless化の評価。REST API活用でNext.jsフロントエンド開発
- **Phase 2（3〜6ヶ月）**: コンテンツのヘッドレスCMS移行
- **Phase 3（6ヶ月〜）**: WordPressバックエンドの段階的廃止

---

## 4. 推奨移行先

| 現在 | 推奨 | 理由 |
|---|---|---|
| PHP + WordPress | Next.js 14 | 高速・SEO対応・型安全 |
| MySQLカスタムテーブル | PostgreSQL / Supabase | モダンなDB設計 |
| PHPプラグイン | npm パッケージ | 豊富なエコシステム |
| Gutenbergブロック | MDX / Contentlayer | 開発者フレンドリー |
